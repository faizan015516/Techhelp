Example: Windows says the document printed, but nothing came out

When a job disappears from the Windows queue, it does not necessarily prove that the printer produced a page. Use this sequence to identify where the failure starts:

  1. Confirm the destination: In the original app's Print window, check that your physical printer was selected—not Microsoft Print to PDF, another printer, or a disconnected old printer entry.
  2. Check the device: Look for paper, cover, ink/toner and error messages on the printer's own panel. Then try its built-in status/test page, if your model supports one.
  3. Compare outcomes: If the built-in test prints but the Windows job produces nothing, examine the selected Windows printer and connection. If the built-in test also fails, stop changing Windows drivers and follow the printer manufacturer's hardware or supplies instructions.
  4. Try one small job: Open a simple text document in a different app and print one page. If it works, focus on the original document, print preview and application settings instead of reinstalling everything.

If jobs remain visible in the queue, use our stuck-print-queue guide. If paper comes out completely blank, use the blank-pages guide instead. These are different faults and shouldn't all be treated as driver problems.

A useful fix follows a useful test.

Power, device errors, connection state and print queues each answer a different question.

1. Check the printer's exact on-device error

Observe: Read the printer screen or light-code explanation for an open cover, incorrect paper, jam, ink/toner warning or initialization state. A powered-on device can still be unable to feed or print. Write down the actual code before changing anything in Windows.

Act on the result: Follow that model's user-accessible instructions. A grinding noise, hot fuser warning or inaccessible jam is a stop condition for qualified support—not a reason to reinstall drivers or force the mechanism.

2. Run a printer-generated test, not a Windows test

Where your model supports it, print a status/configuration page or nozzle-check using controls on the printer itself. This is different from Windows' “Print test page,” which still depends on the PC's driver and connection. If the internal page fails, focus on the device's reported fault and paper/consumables. If it works, that shows the printer can produce at least one local page; it does not prove the USB, Wi-Fi, driver or every color mode works.

3. Test the actual USB or network connection

For USB, inspect both cable ends and, where safe, try a known-working direct port rather than a hub. For Wi-Fi or Ethernet, consult the model's on-device network report and note the current network name and IP address, if available. Do not post the report: it can contain identifiers and other network details. A guest SSID may block local printing; being on the same SSID or subnet is not proof of reachability. If the printer has not joined Wi-Fi, use the Wi-Fi setup guide before touching drivers.

4. Confirm the physical destination in Windows 11

Open Settings → Bluetooth & devices → Printers & scanners, then verify the exact printer selected by your application. Check for a stale duplicate, “Copy 1”, an old office queue or “Microsoft Print to PDF.” If Windows says a job completed but no paper appears, the job may have gone somewhere other than the printer you are watching. A completed job in Windows alone does not prove the intended device received or printed it.

5. Observe the queue instead of guessing its cause

Open the intended printer's queue and record what happens to one simple job: waiting, paused, offline, error, completed or disappearing. If it is paused, check the available resume option; if it reports Offline, compare the printer's actual connection and Windows' saved entry using our Offline guide. A waiting job does not, by itself, prove that Print Spooler is crashing.

6. Cancel your own stuck job first

Cancel just the test or failed document you own, then send one short text-only page. If that succeeds, the first job or its application may have caused the blockage. If every new job remains stuck, investigate the selected queue and Print Spooler separately using the queue guide. Microsoft's procedure treats clearing the entire spool folder as a later step; it can discard other users' print jobs and requires authorization on shared computers.

7. Restart only equipment you control

Save open work and restart your own printer and Windows PC normally, then repeat the same one-page test. A temporary recovery is a useful clue about an intermittent state, not proof that any one component caused the problem. Do not reset shared routers, erase wireless credentials, interrupt firmware updates or disrupt office print queues as an exploratory first step.

8. Compare one text file with the failing document

Print a short plain-text page from a trusted app, followed by the original PDF, spreadsheet or image, selecting the same physical printer each time. Compare document preview, scaling, paper size, duplex, app and queue behavior. If the text page prints but a PDF does not, investigate the document or application before printer-wide maintenance. If both fail identically, the shared Windows printing path or printer state is a more plausible area to test.

9. Change drivers when a driver problem is supported by evidence

A driver-unavailable warning, unsupported model or failure after a specific update warrants checking Windows Update and the manufacturer's official download page. Verify exact model, Windows version and architecture; older devices and Windows on ARM may have special limitations. If the printer works from other Windows applications, replacing all drivers is unlikely to be your best first test. Avoid third-party “driver fixer” advertisements. See driver compatibility.

10. Run Windows Get Help and preserve your observations

Open the Get Help app and search for printer troubleshooting. If unresolved, record the device model, connection type, on-device error, built-in print result, second-device result, Windows queue name and outcome of the simple document test. This is actionable information for manufacturer support and network administrators. Exclude passwords, private serial numbers and entire network reports from public posts.

Original diagnostic framework · Worked example, not a device test

Four observations that isolate the failing print stage

Perform only the tests your printer supports. Do not infer a hardware fault from a single Windows popup. This evidence matrix explains what a result supports—and what it does not.

Controlled comparisonWhat the outcome suggestsWhat it does not establish
Built-in page fails before Windows is involvedInvestigate the printer's own error, feed path or supplies firstA particular broken sensor, cartridge or driver
Built-in page works; another trusted device printsCompare this PC's destination, driver and print queueThat all network or app problems are ruled out
Plain text prints; one PDF or photo job failsCompare preview, document complexity and app-specific settingsThat the physical printer is broken
Windows reports Completed; expected printer stays idleVerify the selected physical printer, old entry or virtual destinationThat paper emerged from the intended device

Illustrative case: an office printer produces its own status sheet, and a second authorized laptop prints. The first PC sends a job to an old “Printer (Copy 1)” entry, marks it complete, but the expected printer stays idle. That sequence makes checking the saved Windows destination a better next step than replacing ink or factory-resetting the router. The case is a reasoning example, not a claimed repair performed by Printer Resolve.

Frequently asked questions

Why is my printer connected but not printing?

A Wi-Fi connection alone does not confirm that Windows can send jobs to the printer. Check whether Windows selected the right printer, whether jobs are stuck, and whether the printer has an error on its own display.

Why does my printer say printing but nothing comes out?

The job may be waiting in a queue or the printer may be paused or unavailable. Open the print queue, look for errors and try a built-in printer test page. See our print queue troubleshooting guide.

What if the page comes out blank?

That is a different symptom. See our printer printing blank pages guide for checks related to ink, toner, print settings and printheads.

If the printer shows a paper-jam warning although no paper is visible, follow our paper jam but no paper stuck troubleshooting guide before changing Windows settings.

When the print is cropped at the edges rather than blank, try our cut-off text and page margins guide.
