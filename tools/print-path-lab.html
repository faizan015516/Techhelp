Find the failing layer before changing a setting.

A printer may generate its own page successfully while Windows cannot deliver a job—or the reverse. Record four observations and this worksheet explains what they suggest, what they do not prove, and the next low-risk test.

    How to collect reliable evidence

    Start with the printer's own status. Check the display for paper jams, cover warnings, ink/toner problems or connection errors. If your model supports an internal configuration or status page, follow its official instructions to produce one without using Windows. A normal device page suggests the basic paper-feed and print mechanism can function; it does not prove the Wi-Fi or driver is working.

    Compare a second device only when safe. A trusted second phone or laptop already configured for that printer can be a useful control. If it prints normally, focus on the original PC's selected printer, saved port, spooler or app. If it fails too, look at shared causes such as the printer state or network. A second-device failure does not prove the printer is physically broken.

    Use the printer's current network record, not a remembered address. Many printers can show their joined SSID and local IP address in a network report. A computer using a guest or isolated wireless network may not discover a printer even if both devices show Wi-Fi. The IPv4 range calculator can help compare addresses, but being in the same calculated subnet does not guarantee reachability, and different subnets can still communicate when routing permits.

    Inspect Windows without clearing other people's print jobs. In Windows 11 open Settings → Bluetooth & devices → Printers & scanners, choose the relevant printer and inspect its queue. The exact menu wording may vary by Windows version. Confirm you selected the physical printer rather than “Print to PDF,” an older duplicate or a device at a previous address. On work or school equipment, ask the administrator before changing shared settings.

    Advanced Windows observations, only when they help

    For a network printer with a verified IP address, Windows PowerShell includes the read-only Get-PrinterPort command. It lists configured printer ports on that Windows machine. A saved address that differs from the printer's current report can be useful evidence—but some printers use WSD or other discovery mechanisms, so not every printer will display a simple IP-based port.

    The Windows Test-NetConnection -ComputerName 192.168.1.50 -Port 9100 command can test TCP connectivity to port 9100 only if the exact printer or print server is documented to use RAW TCP/9100. Replace the sample address with a verified device address. A failed test on an unsupported port proves nothing about printer health; an open port does not guarantee a functioning driver or print job. We do not run this command from the website.

    ICMP ping results have similar limits: a disabled or filtered ping response is not enough to declare a printer unreachable. Use the manufacturer's documentation to determine the supported print protocol. Avoid opening router ports to the public internet to fix local printing.

    Stop condition: If the printer warns of an internal hardware error, a hot or electrical component, or repeated maintenance failure, follow the manufacturer manual or use qualified service. On a managed network, coordinate changes with the administrator. Do not disable antivirus, erase an entire shared spool queue or factory-reset a router just to follow this worksheet.
